## [A] Что это такое

**Суть проекта.**
WebSales — Cloudflare Worker, который загружает акционные товары из трёх
украинских продуктовых сетей (Сільпо, Novus, Фора), нормализует их в единый
формат и показывает в одной HTML-странице с фильтрами по скидке, поиском
и сортировкой.

**Задача / проблема, которую решает.**
У каждой сети собственный сайт с разной структурой каталога и разной логикой
акций. Сравнивать цены и скидки между магазинами вручную неудобно. WebSales
сводит всё в один список «на одной странице».

**Целевая аудитория.**
- Конечные пользователи в Украине, охотники за скидками в этих трёх сетях.
- Разработчики, которые поддерживают/расширяют интеграцию.

## [C] Функциональность

### ✅ Реализовано и работает

- **Загрузка категорий с трёх магазинов** — `/api/{silpo|novus|fora}/categories`.
- **Загрузка товаров по списку ID категорий** — `/api/{store}/products?category=id,id,…`.
- **Объединённая таблица товаров** с поиском, сортировкой и фильтром по диапазону скидки.
- **Дедупликация** товаров по стабильному ключу `store:id` (а не по имени — иначе
  одинаковые названия из разных магазинов склеились бы в одну запись).
- **CORS** — заголовки `Access-Control-Allow-Origin: *` и методы `GET, OPTIONS`.
- **Hardened headers для HTML** — `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: strict-origin-when-cross-origin`.
- **Кэширование ответов API** через Cloudflare Cache API (TTL 1 час для категорий,
  15 минут для товаров, заголовок `X-Cache: HIT|MISS`).
- **Структурированный JSON-лог** (`logInfo` / `logError`).
- **Retry с экспоненциальным backoff** — для 5xx и сетевых ошибок; 4xx и таймауты
  не повторяются.

### 🔧 В процессе разработки

- **Рефакторинг структуры** (видно в незакоммиченных изменениях):
  выделены `utils/http.js`, `providers/registry.js`, `providers/normalize.js`,
  `client/*` (модули для встроенного UI).

### 📋 Запланировано (не начато)

- UI-выбор конкретных категорий (сейчас клиент тянет все непустые автоматически).
- E2E-тесты (Playwright).
- Мониторинг и алерты по статусу провайдеров.
- Расщепление `client/script.js` на модули (на случай роста UI).

## [F] Архитектура

**Тип:** слоистая (Worker → Provider registry → Provider / Adapter → HTTP util →
внешний API) с frontend-монолитом, встроенным строкой в HTML-ответ.

**Основные компоненты:**

- `src/index.js` — Worker entrypoint: маршруты, CORS, parseCategoryParam,
  кэш-обёртка, параллельные запросы по категориям через `Promise.allSettled`,
  единая обработка 500.
- `src/providers/registry.js` — словарь `PROVIDERS` + `getProvider(store)`,
  бросает `Unknown store: …` при отсутствии ключа.
- `src/providers/silpo.js`, `novus.js`, `fora.js` — тонкие фасады,
  конфигурируют адаптер (RPC-стиль для Silpo/Fora, прямой REST для Novus).
- `src/providers/rpc-adapter.js` — общая логика для Silpo/Fora:
  POST-RPC, постраничная загрузка `From/To`, лимит `MAX_PAGES=50`.
- `src/providers/normalize.js` — нормализация одного товара в единый формат.
- `src/utils/http.js` — `fetchWithTimeout` (через `AbortSignal.timeout`),
  `httpGetJson`, `httpPostJson`, `throwIfNotOk` с маппингом ошибок.
- `src/utils/cache.js` — `withCache` через Cloudflare Cache API,
  namespace `websales-api-v1`, заголовок `X-Cache: HIT|MISS`.
- `src/utils/retry.js` — `withRetry` с экспоненциальным backoff.
- `src/utils/logger.js` — структурированный JSON-лог.
- `src/catalog-utils.js` — `flattenParentCategories` (для плоских списков),
  `flattenNestedCategories`, `findCategoryById` (BFS),
  `mergeProductResults` (дедуп по `store:id`).
- `src/page.js` — собирает HTML-оболочку `<head><style>…<body>…<script>…`.
- `src/client/styles.js`, `page-body.js`, `script.js` — UI как ESM-строки.

**Поток данных (текстом):**

> Браузер → GET `/` → HTML-оболочка с UI.
> Кнопка «Знайти» → fetch `/api/{store}/categories` → fetch
> `/api/{store}/products?category=…` → на сервере: `withCache` →
> `getProvider(store).getProducts(...)` → `rpc-adapter` / `novus` →
> `httpGetJson` / `httpPostJson` → внешний API → нормализация →
> `mergeProductResults` (дедуп) → JSON-ответ → клиент фильтрует / сортирует /
> рендерит.

## [G] Модели данных

**`Product` (нормализованный, единый для всех магазинов):**

- `id: string` — стабильный ключ (`store:id`).
- `store: string` — отображаемое имя магазина («Сільпо» / «Новус» / «Фора»).
- `name: string` — название товара.
- `category: string` — название категории.
- `price: number` — текущая цена (в гривнах).
- `oldPrice: number | null` — старая цена до скидки.
- `discount: number | null` — процент скидки.
- `unit: string` — единица измерения (`шт`, `кг`, `л`, `мл`, `г`).
- `url: string` — ссылка на товар в магазине.
- `image: string | null` — URL картинки (или превью).

**`Category` (для UI):**

- `id: string | number` — стабильный идентификатор.
- `slug: string` — URL-slug (или `id`, если slug нет).
- `title: string` — название.
- `count: number` — количество товаров в категории.
- `parentId: string | number | null` — ID родителя (для иерархии).

**`ApiProductsResponse`:**

- `total: number` — количество товаров **после** дедупликации.
- `rawTotal: number` — количество товаров **до** дедупликации.
- `products: Product[]` — массив нормализованных товаров.
- `errors: string[]` — опционально, если часть категорий упала, но общий
  ответ ещё можно вернуть.

**Связи между сущностями (текстом):**

> Один магазин 1↔N категории. Одна категория 1↔N товары.
> Один товар принадлежит ровно одному магазину (поле `store`).
> Дедупликация работает по `store:id` — два товара с одинаковым именем из
> разных магазинов считаются разными.

## [H] API / Контракты

**REST / HTTP (только `GET` и `OPTIONS`):**

- `GET /` или `GET /index.html` — отдаёт HTML-страницу (`text/html`,
  hardened headers).
- `GET /api/silpo/categories` — список категорий Сільпо.
- `GET /api/silpo/products?category=<id[,id,…]>` — товары Сільпо.
- `GET /api/novus/categories` — список категорий Novus.
- `GET /api/novus/products?category=<id[,id,…]>` — товары Novus.
- `GET /api/fora/categories` — список категорий Фора.
- `GET /api/fora/products?category=<id[,id,…]>` — товары Фора.
- `OPTIONS *` — CORS preflight (`Access-Control-Allow-Origin: *`).
- Любой не-GET/не-OPTIONS → `405 Method Not Allowed`.
- Неизвестный путь → `404 Not Found`.

**Формат ответа товарного endpoint'а:**

```json
{
  "total": 0,
  "rawTotal": 0,
  "products": [],
  "errors": []
}
```

`errors` включается только если часть запросов по категориям упала,
но общий ответ всё ещё осмыслен.

**Кэш-заголовки:** `X-Cache: HIT|MISS`, `Cache-Control: public, max-age=<ttl>`.

## [I] Экраны / Навигация

Приложение — single-page HTML без роутинга. Один экран.

**Список блоков экрана:**

- **Хедер** — название «WebSales · Система пошуку акцій», подзаголовок
  «Сільпо · Новус · Фора — усі знижки в одному місці».
- **Тогл «▼ Фільтри»** — сворачивает/разворачивает панель фильтров
  (на экранах ≤ 420 px по умолчанию свёрнута).
- **Чипы магазинов** — «Сільпо / Новус / Фора» (toggle active);
  позволяют выбрать, какие магазины участвуют в поиске.
- **Поле поиска** — фильтрует по `name | category | store` (без учёта регистра).
- **Два поля `discountMin` / `discountMax`** — диапазон скидки
  (по умолчанию 35–60 %).
- **Кнопка «Знайти товари»** — запускает загрузку.
- **Sort-бар** — четыре кнопки сортировки:
  ↓ Знижка (по умолчанию), ↑ Ціна, ↓ Ціна, А–Я.
- **Карточки товаров** — изображение / название / бейдж магазина + категория /
  текущая и старая цена / бейдж скидки (hot ≥ 50 %, mid ≥ 20 %) /
  ссылка «Відкрити в магазині →».
- **Статус-бар** — «Знайдено: N товарів» + сообщения об ошибках / дубликатах.

**Навигация (текстом):**

> Главный экран (/) → тогл фильтров (раскрывает/скрывает панель)
> → выбор чипов магазинов → ввод поисковой строки / диапазона скидки
> → кнопка «Знайти» → ожидание ответа → рендер карточек / empty-state.

## [O] Проблемы и технический долг

### Известные баги

1. **Нет UI для выбора категорий** — клиент всегда грузит все непустые
   категории и запрашивает все товары разом. На больших магазинах это
   может быть медленно / дорого по кэшу. Серьёзность: **средняя**.
2. **Нестабильность внешних API** — README явно предупреждает, что
   store APIs могут меняться без предупреждения. Сейчас нет мониторинга
   / алертов. Серьёзность: **средняя**.

### Технический долг

1. **Незакоммиченный рефакторинг** — много `modified` файлов, удалён
   `utils/fetch.js` без фиксации в git. Нужно стабилизировать и закоммитить.
2. **Дублирование retry-логики** — в `rpc-adapter.js` и `novus.js`
   вызовы `withRetry` расходятся параметрами (`maxRetries` 2/0/2).
   Нет единой политики ретраев.
3. **`client/script.js` — 292 строки в одной строке-template** —
   при росте UI его надо расщепить (на это прямо указывает README).
4. **Захардкоженные `id` под Киев** в `wrangler.toml` — для другого
   региона придётся менять вручную, нет конфигурации по городам.
5. **Хеканый `storeKey` в клиенте** — `replace('і', 'i')` для маппинга
   «Сільпо» → `silpo`. Фрагильно для будущих магазинов.
6. **Дедуп строго по `id`** — товары без `id` никогда не дедуплицируются
   и попадают каждый раз. Может быть неожиданным поведением.

### Принципиальные ограничения

- Система **не хранит состояние** — никаких пользователей, истории,
  избранного. Только актуальные акции на момент запроса.
- Система **не индексирует** — каждый запрос идёт к store API напрямую
  (через кэш).
- Система **не делает авторизацию** — все endpoint'ы публичные, CORS `*`.
- Система **не сравнивает** товары по содержимому — только по
  метаданным (название, цена, скидка, изображение).

## [P] Важно знать

### Нестандартные решения, хаки, подводные камни

1. **UI встроен в JS-строки** — `styles.js`, `page-body.js`, `script.js`
   экспортируют template literals, которые склеиваются в `src/page.js`.
   Никакой сборки, никакого bundler-а, никаких CSS-файлов.
2. **Кэш-ключ — это URL** — `new Request(request.url, { method: 'GET' })`.
   Разный query — разный кэш (это и плюс, и минус).
3. **Namespace кэша `websales-api-v1`** — при несовместимой смене схемы
   ответа нужно бампнуть версию, иначе клиенты получает старый формат
   из кэша.
4. **`MAX_PAGES = 50` в `rpc-adapter.js`** — защита от бесконечной
   пагинации. При `pageSize=50` (Fora) это 2500 товаров на категорию,
   при `pageSize=100` (Silpo) — 5000.
5. **rpc-adapter считает товар постранично через `From/To`** —
   `offset` инкрементируется, `total` приходит из `itemsCount` ответа
   и используется для ранней остановки.
6. **`storeKey` в клиенте** хекается через `replace('і', 'i')` —
   фрагильно для будущих магазинов с украинскими буквами в имени.
7. **4xx и `TimeoutError` не повторяются** — `withRetry` пропускает их
   сразу. 5xx и сетевые — ретраятся с экспоненциальным backoff.
8. **CORS `*` для API** — UI технически может хоститься отдельно,
   но прод-деплой предполагает тот же домен.

### Что нельзя трогать без последствий

- `wrangler.toml [vars]` (другие ID сломают запросы к store API).
- Имя кэша `websales-api-v1` (смена = двойной кэш на rollout).
- Формат `Product` (все три провайдера + UI завязаны на него).
- TTL в `index.js` (`CATEGORIES_TTL=3600`, `PRODUCTS_TTL=900`) —
  изменение повлияет на свежесть данных.

### Соглашения в кодовой базе

- **Именование:** ESM-импорты через `.js`; kebab-case для файлов,
  camelCase для функций и полей.
- **Структура модулей:** функции (не классы); `env` всегда идёт
  последним параметром; `ctx` идёт перед `env` в `withCache`.
- **Доступ к данным:** всё через тонкие `provider`-фасады + общий
  `rpc-adapter` / прямой REST для Novus.
- **Обработка ошибок:** ошибки бросаются наверх в `index.js`,
  где превращаются в единый `500 Internal Server Error`.
  Частичные ошибки по категориям собираются в `errors[]` ответа.
- **Логирование:** структурированный JSON через `logInfo` / `logError`.
- **Кэширование:** оборачивается через `withCache(request, ctx, fetcherFn, ttl)`.
- **Retry:** оборачивается через `withRetry(fn, maxRetries, baseDelayMs)`.

## [Q] Глоссарий

- **`filialId`** — ID конкретного магазина/филиала сети (Сільпо / Фора);
  определяет, по какому магазину возвращаются цены и наличие.
- **`merchantId`** — ID юрлица / мерчанта (только у Фора).
- **`deliveryType`** — тип доставки (`DeliveryHome` у Сільпо — строка;
  `2` у Фора — число).
- **`RPC-style API`** — у Сільпо и Фора категории и товары запрашиваются
  одним POST с JSON-RPC-телом `{ method, data }`.
- **`Zakaz-стиль`** — у Novus внешний API — `stores-api.zakaz.ua`,
  постраничная выдача с `?page=N` и `next`-флагом.
- **`RPC-adapter`** — общий адаптер для двух store, использующих RPC-стиль.
  Создаётся через `createRpcAdapter(config)`.
- **`Provider`** — абстракция магазина: `{ getCategoryTree, getCategories, getProducts }`.
- **`storeName`** — отображаемое имя магазина для UI («Сільпо» / «Новус» / «Фора»),
  а не slug.
- **`rawTotal` vs `total`** — `rawTotal` — до дедупликации,
  `total` — после. Помогает UI показать «без дублів: N».
- **`websales-api-v1`** — имя namespace в Cloudflare Cache API;
  версия зашита в строку.
- **`getStableProductKey`** — формирует ключ дедупа вида
  `${store}:id:${id}`. Без `id` ключ = `null` и дедуп не работает.
- **`MAX_PAGES`** — лимит страниц в `rpc-adapter.js` (50).
- **`AbortSignal.timeout`** — встроенный в `fetch` механизм таймаута,
  используется в `utils/http.js`.
